# WJ-888 · Jobs · DONE

**What:** For a job a role's search found, its résumé, cover letter and form answers are now drafted from that role. A job found any other way still uses My profile.
- **What the role supplies:** Role you want becomes the résumé headline, plus the role's goal, level and skills.
- **What stays shared:** work history, education, contact and strengths.

**Where it applies:**
- Generate Customized Resume / Re-generate Resume on the job page.
- Prepare (résumé, cover letter, answers).
- The run's own preparation of the top matches.
- Apply's form answers and the questions drafted there.

**Choosing the profile:** with roles, one line above the résumé button, "Built for [profile ▾]", names the profile and picks another for the next Re-generate. It defaults to the profile the last résumé for this job was built from, else the one whose search found the job. A saved résumé records the profile in `target.builtFor`.

**Why:** Owner, 2026-11-26: "when i searched under reinsurance … it worked, but when it generated the custom resume, it still picked the other profile, fix this". Every draft used My profile's `dna` whatever role found the job.

- The role's own résumé file was already offered first on Apply and Prepare (`baseResumeFor`, unchanged). The customized résumé is built from the profile, not from a file.
- Small generic change to WonderWorks' `ResumeButton`: optional `profile`, `builtFor` and a `chooser` slot. Internships and Teaching pass none, so they're unchanged.

- AI governance is unchanged. The customized résumé calls no model. Prepare's drafts still go through `services/ai/service.ts` and are labelled AI-generated.
