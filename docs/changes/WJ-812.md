# WJ-812: WonderWorks Network — messages, one inbox, Updates, and sharing listings to your network

- **What:**
  - **Messages** between connections: Message on a connection's profile opens the conversation (`/app/network/messages/<connection>`).
  - **One inbox** (`/app/network/messages`): every conversation the member has on WonderWorks in one list, each marked Connection, Recruiter, Co-founder or Buy & Sell, and opening where it lives. It reads each module's existing list once, in parallel; nothing is copied.
  - **Updates** tab on Network: what connections did and chose to share. That is a new current role, a status turned on (Open to work, Hiring, Looking for a co-founder, Offering services), or a listing shared from any module, each with its module's name.
  - **My network** on every Share sheet (the shared `ShareButton`, so every module and Jobs): shares the listing's public page with the member's connections.
- **Why:** Owner request (2026-11-20): Updates in the first release, and Network connected to every module as far as possible.
- **Notes:**
  - No migration: the tables came with WJ-811 (`0051_network.sql`).
  - **Security / governance:**
    - A conversation is read or written only by the two people on a connected, unblocked connection; anyone else gets "not available".
    - Sending goes through `resolveCapability("network.message")` and is audited as `MESSAGE_SENT`, without the words. The notification names nobody.
    - Updates show only the viewer's own connections' updates.
    - A shared listing must be a public listing page (`/j/<id>` or `/s/<module>/<id>`); the module is taken from that path, and the same page isn't shared twice. At most 20 shares a day.
  - Not in this PR: a link from a Co-founders or Talent profile to the same person's network profile. That needs each module to map its own people to network ids, which is each module session's change.
  - Tests: `server/network/social.test.ts` (who can read and write, removal, block, updates scope, share validation).
