# WJ-854: Next.js 16.4.3 → 16.4.6 (security)

- **What:** `next` and `eslint-config-next` go from 16.4.3 to 16.4.6, the latest patch release. Only `apps/web/package.json` and `package-lock.json` change.
- **Why:** `npm audit` listed seven moderate advisories for next ≤ 16.4.4. Among them: cross-user disclosure and poisoning of `use cache` results (GHSA-rhh4-g77r-r9qj, GHSA-vc7v-qv4w-wrv8, GHSA-mfr8-8qww-v76h, GHSA-vvgp-ww4w-46vf), exposure of HttpOnly cookies on Edge routes (GHSA-f3mh-rxg3-f5g2), response injection when forwarding fetched responses (GHSA-pc58-hwjq-p385) and an SVG bypass in image optimisation (GHSA-7qx7-33qx-rqx2). The local build also stopped with Next's own security notice. The owner approved the upgrade on 2026-11-22.
- **Notes:**
  - After the upgrade `npm audit` no longer lists `next`.
  - Typecheck, the local production build and all unit tests (3,183) pass.
  - The audit still lists moderate advisories in the `typescript-eslint`/`minimatch` dev tooling. They are untouched here, since they never ship to users.
  - Lockfile change: per CLAUDE.md, it merges alone.
- **PR:** see the squash commit.
