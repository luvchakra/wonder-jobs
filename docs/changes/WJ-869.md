# WJ-869: A listing from a post opens on its module's own page

- **What:**
  - On the signed-in view of a listing someone shared (`/app/network/listing/<module>/<id>`), the button is now **Open in <module>** (was "Find it in <module>", which only opened the module's Find). It reads the listing and opens the module's own details page (`/app/m/<module>/listing/<id>`), with everything that page offers: Save, RSVP, Apply, Request…
  - If the listing can't be had (it closed), the module's Find opens instead.
  - Module pages read listings from the person's saves and last search (`wonderworks/store.ts::findListing`). They now also read listings opened this way, held in memory for the visit only, never stored or synced (`rememberOpened`). No module code changes.
- **Why:** Owner request (2026-11-23), on the shared listing page: "on click take user to the details page of this entry directly".
- **Notes:**
  - `server/share/listing.ts` returns the listing itself next to its share (`moduleListing`), from the same public record the share page reads. `/api/network/listing` serves it to anyone signed in (in the network routes' sign-in check).
  - Help is updated (Network).
  - Unit test: `share/listing.test.ts`.
- **PR:** see the squash commit.
