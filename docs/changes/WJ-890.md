# WJ-890 · Jobs · DONE

**What:** A role with its own résumé file is now that file's person. Everything built for that role's jobs comes from the file alone:
- the customized résumé and Re-generate;
- Prepare's cover letter and answers;
- the run's own preparation;
- Apply's form details.

That means the file's name, contact, headline, history, education and skills. The role's Role you want, level and skills still go over them, and nothing is mixed in from My profile. Generated files take the file person's name (Deepak_Poojari_Resume_…). Under "Built for" one line names the file ("From Deepak_Poojari_CV_Sample.docx").

While the file is being read, or if it can't be read, nothing is built:
- the job page says "Couldn't read <file>: <reason>";
- Prepare says the same;
- the run skips the job with a note;
- Apply leaves the details empty and asks for them.

It never falls back to the account holder's details. Roles without a file are unchanged (My profile plus the role's fields).

**Why:** Owner, 2026-11-26: "for reinsurance the profile picked up should be deepak not Kunal". The Reinsurance role's résumé is Deepak's, but #814 built from the shared Career Profile, which is Kunal's.

**Notes:**
- `domain/career/roleFile.ts`: `dnaFromReading` turns the stored-file reading into a profile; `dnaFromDocument` does the same for a Resume Studio résumé chosen as a role's résumé.
- `lib/useRoleFile.ts`: `useRoleFile`, `loadRoleFile`, `jobProfile` and `roleFileLine`.
- A stored file is read through `/api/resume-files/[id]/read`, the same reading Update from your résumé uses (tenant-checked and rate-limited, no change there). Readings are cached in memory per file id, at most 8. A replaced file has a new id, so it's read again. A failed read is tried again next time.
- Apply doesn't pass the account email for a file person.
- WonderWorks' `ResumeButton` gains an optional `unavailable` reason, which shows a message instead of building. This is a small generic change; other modules pass none.
- Caveat for the owner: a role added after #807 starts with My profile's skills (prefill). Those skills are the role's own and still go over the file's, as asked. Clearing them makes the file's skills show.
- Tests in `roleFile.test.ts` cover:
  - a Deepak résumé carries only Deepak's name, contact and history;
  - a role without a file uses the Career Profile;
  - reading or failed builds nothing and the line says so;
  - a Resume Studio résumé round-trips.
- Checked at 390px with a saved résumé renamed to Deepak Poojari as the role's résumé. With Reinsurance picked, the line reads "From Deepak_Poojari_CV_Sample". The new résumé's header is Deepak's name, email and phone with the headline "Head of Reinsurance Operations", and no trace of the account holder. No sideways scroll.
- The uploaded-file path isn't checked in the browser here, because the dev server stores no files. It is covered by the unit test of `dnaFromReading` over the reader's output.
- AI governance is unchanged: Prepare's drafts still go through `services/ai/service.ts` and are labelled AI-generated.
