# WJ-773 · Platform (shared) · DONE

**What:** The gateway collection and the Find refresh run on the GitHub Actions runner, not on Vercel.
- **The workflow** (`.github/workflows/gateway-collect.yml`, every 3 hours) checks the code out and runs `apps/web/scripts/gateway-collect.mjs`, which loads the app's own collection code (`server/gateway/runner.ts`) through jiti and runs it against Supabase with the repository's secrets. The site is never called.
- **One process, minutes not seconds:** the runner finishes any Setup job left over, collects every due source (20-minute budget), refreshes every module's Find, drains the Setup job to the end and emails the admins. The hops, hand-ons and 12–48 s deadlines built for Vercel's 60 s stay for the site's own fallback path but aren't used here.
- **Import now / Import this module** on Admin → Sources → Import start that same workflow (`server/gateway/dispatch.ts`, `workflow_dispatch`) when `GITHUB_DISPATCH_TOKEN` is set on the deployment; otherwise they run on the site as before. The page says which.
- **"Run workflow" by hand** on GitHub takes a mode (scheduled, all, module), a module and who started it.
- **Vercel's own daily collection cron is removed** (`vercel.json`); `/api/cron/gateway-collect` stays as the fallback the workflow calls until the runner's secrets exist.
- **Email wording:** "The scheduled collection finished" (it said "hourly"; the schedule is 3-hourly).

**Why:** Owner, 2026-11-06: "Move the collection and Find refresh off Vercel onto the GitHub Actions runner that already triggers it … leaving the site to serve pages. This is the real fix" — after Vercel paused the project for exceeding the Hobby plan's Active CPU allowance. The repository is public, so GitHub Actions minutes are unlimited.

**Notes:**
- **Secrets on the runner:** SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, SECRET_ENCRYPTION_KEY (the exact value the site uses, or the admin's stored keys can't be read), GATEWAY_ADMIN_TOKEN, GATEWAY_CURSOR_SECRET, WORKSLAKE_GATEWAY_API_KEY, SMTP_*, CONTACT_NOTIFY_EMAILS; variable SITE_URL. Listed on Admin → Sources → Import (`OWNER_DECISIONS`: collection-runner-secrets) and in `.env.example`.
- **Governance:** the same code and checks run (robots, crawl delays, the 6-hour floor per source, one Setup job at a time with its lease). The dispatch token is a fine-grained token with Actions read/write only, never sent anywhere but GitHub's API, and GitHub's answer text never reaches the admin.
- **Fallback:** without the secrets the workflow still collects through the site (with a warning), so nothing stops during the move.
- **Tests:** `runner.test.ts`, `dispatch.test.ts`, `collectJob.test.ts` (runner options), `importEmail.test.ts`. The script's module graph was smoke-loaded through jiti locally (`WJ_RUNNER_CHECK=1`); a real run on the runner waits on the secrets.
- **On the owner:** add the secrets in GitHub; set `GITHUB_DISPATCH_TOKEN` on the (new) Vercel project.
