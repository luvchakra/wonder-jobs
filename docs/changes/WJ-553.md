# WJ-553 · Jobs, WorksLake · DONE

**What:** New Jobs source **JSearch (Google for Jobs)**. It brings in listings Google for Jobs gathers from LinkedIn, Indeed, Naukri, foundit, TimesJobs and company career sites. Each listing is marked with the board it came from ("via LinkedIn"), and Apply opens the employer's own page when Google lists one, else the board's. It shows "Needs setup" until `JSEARCH_API_KEY` is set on Admin → Keys, which has a Test for it.
**Why:** Owner, 2026-11-05: "yes add JSearch" (relayed by the shared-layer session).
**Notes:**
- **When it's asked:** only on a worded search, live and cached like the other On-search sources. It sends one request per country the search names, up to 3; JSearch defaults to the US, so a place we can't put in a country isn't searched. It is asked with the searcher's own words only, never each broader phrasing. The new generic `SourceRecord.onePhrasing` flag does this, a small edit in shared `core.ts`/`types.ts`.
- **Daily cap:** `JSEARCH_DAILY_MAX`, default 150, counted per UTC day in the platform state store. Requests are counted before they're sent. Past the cap the source reports Unavailable, "Daily limit reached".
- **Licensing:** the source is licensed, so API keys never reach it.
- **Terms pending:** JSearch collects Google for Jobs listings; neither Google nor the boards have agreed. Confirm JSearch/RapidAPI terms on storing and showing results. This is recorded in the source's `statusReason` and `docs/EXTERNAL_DATA_SOURCES.md`.
- **Tests:** `server/jobs/jsearch.test.ts`, plus `core.test.ts` (one phrasing).
- **Owner to do:** set `JSEARCH_API_KEY` on Admin → Keys and press Test.
