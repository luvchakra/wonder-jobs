# WJ-727 · Platform (shared) · DONE

**What:** The scheduled collection's chain of calls is driven by the GitHub workflow, not by the app calling itself. Each call answers with `next` (hop, chain id, modules still to refresh) when more is due. `gateway-collect.yml` calls each `next` in turn, up to 30 calls, trying a failed call once more. A call marked `x-wj-driver: external` never calls the app itself; Vercel's own daily cron keeps the self-call as a fallback.
**Why:** The first live chain (2026-11-05 20:56 IST) ran 5 calls and collected 9 sources, then stopped with 16 still due. Vercel refuses a call from the app to itself after about five in a row ("508 Loop Detected"), which is also the likely cause of the 508s seen during the Find refresh (docs/DATA_SOURCE_ISSUES.md #7).
**Notes:** The workflow's timeout is 30 minutes (public repository, so Actions minutes are free). No security change: the same CRON_SECRET, and the header only turns the self-call off.
