# WJ-850: Admin → Keys: play and stop per key, with keys that work together in one card

- **What:**
  - Every key that a data source uses gets a **play button** on its card.
    - It runs, now, every source that uses that key, in every module. Adzuna's keys, for example, run five sources in Jobs, Internships and Teaching.
    - Each source is read the way the scheduled refresh reads it: the newest listings, no search words. What it finds is stored in that module's WorksLake listings and recorded as a run.
  - While a run is going, the same button becomes **Stop**, which ends the run before its next source.
  - Each card shows what the button runs ("Play runs 5 sources: Jobs, Internships, Teaching"). During and after a run it shows progress or the outcome: listings found, sources read, and any that failed and why (for example "Needs setup").
  - **Keys that make up one source together** (Adzuna's ID and key, USAJOBS' key and email, Flipkart's, eBay's, Reddit's, CLIST's) now sit in one card with a single play button.
- **Why:** Owner request (2026-11-22): "add a play button on the right side in each card to run the associated job just related to that key, of already running, add option to stop the job. of multiple keys make up a single source of data then show them in a way that shows they belong together and show a common play button".
- **Notes:**
  - Server: `server/jobslake/keyRuns.ts`. Key families come from Test's own pairs (`keyTest.ts::KEY_FAMILIES`). A family's sources are the built-in sources whose id names the provider.
  - Each family's last run is kept in `wj.keyruns` (platform tenant): counts and outcomes only, never a value.
  - The route `api/jobs-lake/admin/keys` gains `action: "run" | "stop"`. The run does its work after the response (`after`), within one server call's budget. A run that loses its server call shows as stopped after three minutes.
  - The page refreshes every 3 s while a run is going, and only while the page is visible.
  - Admin only, audited (`platform_key.run_started` / `run_stopped`). It never runs a search on a person's behalf. Keys with no source (prospect lookups) have no play button.
  - Tests: `server/jobslake/keyRuns.test.ts`.
