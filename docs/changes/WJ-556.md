# WJ-556 · Jobs · DONE

**What:** A running search's banner now reads "392 postings checked in 19 sources" (it counts every posting the sources sent, the same job on several sites included), not "392 found so far". Under a mode's results, the same words' jobs the other mode lists now show: in Part Time, "Also full-time · N for “…”" with the first three, each tagged with its job type, and "See all N in Full Time Jobs", which switches to Full Time and keeps the words and the jobs on screen (in Full Time, "Also part-time"). When only the other mode has any, the page says "No part-time roles for “…”" with "N full-time roles found — they're below." instead of "None of your N jobs match" and "Search every source".
**Why:** Owner, 2026-11-22/23: Part Time "reinsurance" said "392 found so far in 19 sources", then "None of your 293 jobs match" with Search every source; "think of an option to show full time jobs results as well so it gives a full picture".
**Notes:**
- Cause: Part Time leaves out full-time jobs (`other_mode`), and that check runs before the words, so the empty state blamed the words and offered a search that had just run. The new counts come from running the other mode's own filters (its kept Refine, its places) over the same catalog (`domain/jobs/otherMode.ts`), so "See all N" opens exactly N; a job that states no type already shows in both modes and isn't repeated.
- No extra search, no new Refine control; `switchFindMode` takes optional words to keep. Unit tests in `otherMode.test.ts`, `JobsReadiness.test.ts`. Checked at 390px with a seeded Part Time search (empty and mixed cases, and See all → Full Time).
- No automation, AI or external-action change.
