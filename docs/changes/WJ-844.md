# WJ-844 · Tests · DONE

**What:** Tests only. E2E now deletes its disposable accounts the way a person would: signed in, through the product's own "Delete my account" route. The fixed list of tables it used to clear is kept only as the fallback.
**Why:** shared-layer session, 2026-11-21, after WJ-815: the old cleanup knew a hand-kept list of tables, so data in tables the tenant row doesn't cascade to (Network, and whatever comes next) was left in the shared project.
**Notes:** Security and privacy: every signed-in run now exercises real erasure (`/api/privacy/erase` → `eraseAccount` → every `ACCOUNT_DATA` entry) for each account it made. `e2e/fixtures/auth.ts`: `eraseTestAccount` (sign in, erase), `removeTestAccount` (erase, then the old sweep), used by the `account` fixture and by auth, hiring, jobslake, network and real-account specs; an account that already deleted itself in its test is skipped at once. `e2e/cleanup.ts` (global setup) does the same for stale `wj-e2e-*` accounts from a run that was killed: it gives each a new throwaway password, signs in, erases (at most 20 a run), then sweeps. Hooks that delete several accounts set their own timeout (each deletion is a real sign-in, about ten seconds). Not covered, on purpose: `hiring_*` rows. Whether deleting an account should remove a workspace that person owns is a product decision with the owner; the hiring journey's workspaces are still left in the project. Local run on the real project, chromium: auth, help-access, hiring, jobslake and network specs, 39 passed, 0 failed; afterwards no `wj-e2e-*` auth user and no test rows in the `network_*` tables.
