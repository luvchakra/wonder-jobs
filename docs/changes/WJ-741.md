# WJ-741 · Talent & Services · DONE

**What:** The network link on a pro's page is now the poster's own opt-in: "Show my network profile on this listing", a switch on the listing's post/edit form, off by default (every existing listing too). Only the member who posted the listing sees or changes it; another workspace member editing the listing can neither see nor change it.
**Why:** Shared-layer session (2026-11-21), correcting WJ-740: CLAUDE.md lets a module link a person only when the page already shows the viewer who they are; a pro's page names the business and `created_by` may be an employee. Events declined the same case.
**Notes:** Stored in the listing's existing `attrs` JSON (`networkProfile`), so no migration; absent means off. `servicePosterNetworkId` returns null unless it is on, the listing is open and the network gives an id for this viewer. The server ignores `showNetworkProfile` from anyone but `created_by` (their edit keeps the poster's choice) and `orgServices` tells only the poster that they posted it and what they chose; the public postings and terms never carry it. Tests: `server/services/poster.test.ts` (off by default, on only when the poster set it, another member cannot set, clear or see it, never in public terms, plus the earlier network cases). Help updated. Nothing for the owner to apply: the Network tables (migration 0051) are separate.
