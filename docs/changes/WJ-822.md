# WJ-822 · WorksLake gateway · DONE

**What:** A WonderArk search can now name a live source as well as the stored data: Google Places for businesses, YouTube and Podcast Index for channels. Each is listed on `GET /v1/prospects/sources` as "needs setup" until its key is on Admin → Keys, and Prospect data on Sources → Import shows each one's state. A named provider's results follow the stored ones with their own attribution, duplicates merged; Google Places spends 1 paid unit a page from the business's allowance, the other two are free.
**Why:** Stored open data covers only part of India's businesses and no online channels (package A3 of `docs/PROSPECT_DATA_API.md`).
**Notes:** Not built: data.gov.in (its documentation could not be read and its dataset is reported to have no API) and Apollo (cut order; its API terms forbid passing results on without an agreement). None of the three built providers was tried against its real API, as no key exists: mappings are tested with answers shaped as each API reference documents (read 2026-11-11), and Admin → Keys has a Test for each key. Governance: provider keys stay in the app's encrypted key store and are handed to the gateway per request, sent in headers, never logged or returned; a provider's answer is data (markup removed, links checked) and is never written to the listings table; a failing, slow or rate-limited provider says "unavailable" and is not retried; paid units are written before the answer leaves. Terms pending for all three (owner decisions `prospects-live-provider-keys`, `prospects-live-provider-terms`, `prospects-data-gov-in`, `prospects-apollo`). Tests: `apps/data-gateway/test/providers.test.mjs`, `apps/web/src/server/gateway/prospectHooks.test.ts`.
