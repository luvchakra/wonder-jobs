# WJ-734 · Events & Social · DONE

**What:** An event posted on WonderWorks can show "Hosted by <name>" with "View network profile" beside it, but only when the member who posted it turns on "Show me as the host" on the event's post/edit form. It is off by default for every event, existing ones included. Only that member sees or changes the switch; another workspace member editing the event can neither see nor change it. Outside-source events never get the line.
**Why:** Owner, 2026-11-21 (relayed by the shared-layer session, quoted: "yes>>>Decide whether events should show \"Hosted by\" a person"; I can't verify the quote): events show a host person, by the same rule as Talent & Services' posters (WJ-741), so nobody is shown who didn't choose it.
**Notes:** **Security/privacy:** the host is `created_by` (never a workspace owner or anyone else). The choice is stored in the listing's existing `attrs` (`host`), so no migration; absent means off. `server/events/host.ts::eventHost` returns `{ id, name }` only for an open event whose poster turned it on, only when `networkIdFor` gives an id for this viewer, and takes the name from the network's own view of that member for this viewer (`viewMember`: the full name or first name and initial by their tier); with no id, or no view, nothing shows, never a name from the account. Only the public network id and that name reach the browser (`GET /api/m/events/host?listing=`), never an account id or email. `saveEvent` honours `showAsHost` only from `created_by` (any other member's edit keeps the poster's choice) and `orgEvents` tells only the poster that they posted it and what they chose; the public posting never carries it. Attendees stay counts only. Tests: `server/events/host.test.ts` (off by default, on only when the poster set it, poster can turn it off, another member can't set/clear/see it, kept through seat edits and absent from the public posting, nothing when the network gives no id or view, no account id or email). Help updated.
