# WJ-795: An import never stays "paused"; it resumes on its own

**What.**
- A running import no longer shows "It has paused" while it is still working.
- A job that really stopped (for example, its runner died) is picked up again automatically: the page sends it back to the GitHub runner, which finishes only that job (new workflow mode `resume`). The page says "being picked up again automatically. Nothing to do."
- "Try again" appears only if that restart couldn't start. The scheduled run also finishes any job left over.

**Why.** Owner, 2026-11-07: "when it shows paused, what am i supposed to do, cant it auto continue and ensure it finshes?". There were two causes:
- On the runner, setting up one source (a test, then its first collection) takes up to about 2 minutes, but the job renewed its "working" lease (70 s) only between sources.
- Between two rounds of the same run the job briefly had no lease, and the page counted that as stopped too.

**How.**
- `setupJob.ts` renews the lease every 20 s while a source is worked on, and stamps `workedAt` on every save.
- `jobStalled` counts a job as stopped only when no lease is held and nothing was saved for 3 minutes.
- The `continue` route dispatches `resume` to the runner when the runner is set up. It does nothing for a job that hasn't stopped or while a run is already under way.
