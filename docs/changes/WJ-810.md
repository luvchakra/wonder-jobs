# WJ-810: Talent cards like a professional profile, with photo, full profile and résumé

- **What:**
  - Hiring → Talent shows each job seeker as a profile card: a cover band, their photo (or initials), name, headline, level and years, places and work modes, their line for recruiters, and skills with matched ones first (6, then "+N more"). It has Message (primary) and Shortlist, then View full profile and Résumé.
  - View full profile opens everything they chose to show, in About and Skills sections, with Shortlist and Message.
  - On You → Recruiters, job seekers get two new choices, both off by default: Show my profile photo, and Résumé recruiters can open (one of their uploaded files).
- **Why:** Owner request (2026-11-20): "make this card useful for the hiring person, add photo of the user, link to full profile along with link of resume, make it look similar to how LinkedIn profiles look".
- **Notes:**
  - Migration `0050_talent_photo_resume.sql` adds `talent_profiles.show_photo` (default false) and `resume_file_id` (null). It is additive. Until it is applied, a profile still saves; only turning on photo or résumé sharing says it isn't available yet.
  - **Security:** two new cross-tenant reads, each gated three ways. The seeker must have turned it on, the profile must still be open, and the caller must hold `talent.search` in the workspace:
    - `hiring.ts::talentPhoto` → `/api/hiring/[org]/talent/[tenant]/photo`
    - `talentResume` → `/resume`. A PDF opens inline, sandboxed; a Word file downloads.
  - A shared résumé must be one of the seeker's own files (checked against their own file list on save). The file id never reaches a company; it sees only `hasResume`.
  - Turning off Open to recruiters removes the profile, and both reads stop.
  - CLAUDE.md's cross-tenant note is updated. Unit tests cover the gates.
