# WJ-893 · Jobs · DONE

**What:**
- **A chosen place is strict.** With a country or city picked, Find shows jobs in it, plus remote jobs that name it or a region that includes it ("Remote, Singapore", "Remote – APAC").
  - Remote jobs open anywhere ("Anywhere in the World", "Worldwide", "Global", or "Remote" with no place) are hidden then, under their own reason: "remote anywhere, not in the places you picked" (tag "Worldwide remote") in the hidden line and Show hidden.
  - With no place picked, or with "Anywhere"/"Remote" among the places, they show as before.
  - Such a job also loses "Remote friendly" (location 0.55) where a place is picked.
- **The AI check knows the place.** The governed `ai_match` pass (#804) now gets the search's places and work modes. Its prompt tells it that a posting someone there can't take (on-site elsewhere, or "remote, US only" for Singapore) scores under 25, with the limit as its reason. Everything else is unchanged:
  - application code still decides the order;
  - it fails closed to the rules' ranking;
  - it's one call per search;
  - the reason is still labelled AI-generated;
  - postings are still data.
- **The same posting twice is listed once.** Two records with the same title, company, place, work mode and description start (at least 80 characters) count as one. The second is hidden as "the same posting as one already listed". Show hidden doesn't bring it back.

**Why:** Owner, 2026-11-28: "when a specific country is chosen, do not show anywhere options, use ai to determine best search results". With Singapore picked, the top two cards were the same "Anywhere in the World" Ping Identity job.

**Notes:**
- `services/jobs/normalize.ts`: `worldwideRemote`, `strictPlaces`, regions (APAC, EMEA, Americas → their countries and cities), and `inPlaces` made strict.
- Old bug fixed: the worldwide pattern counted "APAC", "Asia", "India" and "UTC+5" as worldwide, so "Remote – India" showed for Singapore.
- `matchesLocations` (the search's own place filter on the server) stays lenient on purpose. Everything it returns is in the catalog, and the list hides it with a reason, so the count stays traceable.
- `domain/jobs/filterExplain.ts`: new reasons `worldwide_remote` and `duplicate`, and `samePostingKey`. `FilteredBreakdown` and `showHidden` list them. `domain/jobs/aiMatch.ts` and `server/ai/systemPrompts.ts::match_jobs` gain places and work modes.
- Duplicates: the root may be two WorksLake gateway records of one job, so the shared-layer session is asked to check the records. This fold is the Jobs-side guard.
- Tests:
  - `normalize.test.ts`: in-country, remote in-country, regional remote, other region, US-only, worldwide, "Anywhere"/"Remote" chosen.
  - `filterExplain.test.ts`: Singapore hides 2 worldwide remote jobs with their reason; "Anywhere" lists them once with the duplicate hidden.
  - `aiMatch.test.ts`: the prompt carries places and work modes; a posting read as not open to the place sinks to a low fit.

  - 3 jobs show, including the APAC one;

- Governance: the AI pass is unchanged in gate (`ai_match` via `resolveCapability`), boundary (`services/ai/service.ts`, server-held prompt with SYSTEM_GUARD) and authority (a read only). Its input now includes the candidate's chosen places.
