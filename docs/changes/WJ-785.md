## Faster crawling with wider coverage

Owner, 2026-11-07: "look for best crawling and scraping strategies in open GitHub projects and online articles, see if you can improve on speed and content scope. design and implement".

**What we drew on:**
- Scrapy's AutoThrottle: a per-site delay that follows the site's response time, never shortened by an error answer.
- Incremental crawling: read new and changed pages first, using sitemap `<lastmod>` and conditional requests.
- extruct-style structured-data extraction: read every embedded record on a page, not only the page's own.
- HTTP compression, standard practice for crawlers.

**What changed (`apps/data-gateway`):**
- **Compressed transfer:** every gateway fetch asks for gzip, deflate or brotli and decodes it. `.xml.gz` sitemap files are read too.
  - HTML, feeds and sitemaps are typically 5–10x smaller over the wire.
  - The size limit applies to the decoded text, so a small compressed body can't expand past it.
- **New and changed pages first:** sitemap `<lastmod>` is kept per URL.
  - A crawl reads pages changed since its watermark first, newest first. The rest continue from the cursor as before.
  - The watermark (`crawlWatermark` on the source) moves on once every changed page has been read.
- **AutoThrottle pacing:** the wait between a site's pages is halfway between the last wait and the site's answer time.
  - It never drops below the site's Crawl-delay (or the source's, at least 1 s) and never exceeds 30 s.
  - A 429 or 503 at least doubles the wait, or follows its Retry-After. Two in a row end the run early, and the next run carries on.
  - The source's HTTP status and Retry-After now travel with the error.
- **Runner-sized runs:** the scheduled collection on the GitHub Actions runner has minutes, not a serverless call's seconds.
  - Each crawl gets up to 4 minutes and 5x its per-run page count (up to 300 pages), 20 child sitemaps and 20,000 discovered URLs.
  - Up to 4 sources run in parallel, never two on the same site. Each site still sees one request at a time at its own pace.
  - Serverless passes keep the old caps: 45 s, 50 pages, one source at a time.
- **More listings per page:** a page's schema.org `ItemList` (and `mainEntity`) is read item by item, so a listing page yields every posting, event or scholarship it carries.

**Not done:** per-URL conditional GET (ETag / If-Modified-Since). It needs per-page state that the gateway's single state document shouldn't hold; the sitemap watermark covers most of the gain.

**Tests:** `apps/data-gateway/test/crawl-speed.test.mjs` (8). The gateway suite passes 92/92. A live check fetched confs.tech's sitemap and w3.org through the compressed path.
