# WJ-764 · Billing (shared) · DONE

**What:** Razorpay is connected from the admin, and paying happens without leaving WonderWorks.
- **Admin → Billing → Payments** (new; the Billing menu opens on it) walks the admin through going live in three steps:
  1. **API keys:** enter the Key ID and Key secret. They're checked with Razorpay before they're saved, stored encrypted, and shown masked. The page shows Test mode or Live mode.
  2. **Webhook:** the URL to copy into Razorpay, the events to tick, and a webhook secret to generate, copy and save.
  3. **Prices:** whether Pro and Max have a Razorpay price, with a link to Prices, which creates them in Razorpay.
- **Going live:** payments count as live once the keys work and Pro has a Razorpay price. The page says so, and from then on the plan switcher (testing, no payment) is for admins only.
- Disconnect removes the keys.
- **Plan & billing (candidate):** Upgrade to Pro / Max opens Razorpay's own checkout window over the page (UPI AutoPay, cards, net banking).
  - When the payment goes through, the plan updates on the spot: "Payment received. Confirming it…", then "Welcome to Pro".
  - Closing the window or a failed payment says nothing was charged. If the window can't load, Razorpay's hosted page opens instead.
  - The card also says when a renewal failed and when a cancelled plan ends.
  - "Needs setup" lines are gone: before payments are live, candidates see only "Paid plans open soon".
  - A paid user moving up is told to cancel first, instead of seeing a button that fails.
- **Admin menu:** Discounts is now reached from Prices, keeping the Billing menu at 5 links.
- **Stripe** stays env-only and isn't offered here (owner: "no need to enable stripe as of now").
- **Also in this PR:**
  - The search box lets go of focus as soon as a search starts, so the phone keyboard closes: Enter, the arrow, a recent search, Search again (`wonderworks/find/parts.tsx::closeKeyboard`). Jobs' `JobFilters.tsx` gets the same one-line call.
  - Logos: the logo URL version is bumped to 4 and a "no logo" answer is cached for 10 minutes instead of an hour, so cards look again soon after a logo is found.

**Notes:**
- **Secrets:**
  - Razorpay keys live under `billing:<NAME>` in the platform credential store, AES-256-GCM, masked on read, never logged.
  - A deployment variable of the same name still wins.
  - Only the Key ID reaches a browser; Razorpay makes it public, and its checkout needs it.
  - Key changes are written to Billing → History by name only, never by value.
- **Governance:**
  - Access still changes only from Razorpay itself: the signature-verified webhook, or Razorpay's own answer.
  - `/api/billing/confirm` checks the checkout's HMAC signature (Key secret over `payment_id|subscription_id`) and checks the subscription is the caller's own.
  - It then asks Razorpay for the subscription's status and ledgers it as a reconciliation. The browser's word is never the status, and a repeat changes nothing.
- **CSP:** Razorpay's checkout hosts are allowed:
  - script: checkout.razorpay.com;
  - frames: api.razorpay.com and checkout.razorpay.com;
  - connections: api.razorpay.com and lumberjack.razorpay.com;
  - images: cdn.razorpay.com.
- `RAZORPAY_PLAN_ID` is no longer required; Prices creates the plans.
- **Tests:** `server/billing/payments.test.ts`.
- **On the owner:**
  1. Enter the Razorpay keys on Admin → Billing → Payments.
  2. Add the webhook in Razorpay's dashboard.
  3. Set the Pro (and Max) price on Prices.
