# WJ-724 · Platform (shared) · DONE

**What:** The gateway no longer refuses a feed that is bigger than its 2 MB read. It reads the feed up to the limit, closes the connection, and keeps every complete item. A feed lists its newest items first, so those are its newest listings; the one item the cut lands in is left out. JSON files and pages can't be read in part, so they are still refused, now as "Response too large" with that reason. We Work Remotely's all-jobs feed ("Feed too large") collects again with no change to its entry. Any future large feed works the same way.
**Why:** Owner, 2026-11-05: "fix this issue with a strategic design" (We Work Remotely: "Feed too large").
**Notes:** `collect.mjs::readBody` (tested with a stream) handles it, and only RSS/Atom sources ask for it (`partial`). The size limit and the "only public addresses" checks are unchanged. The all-jobs source overlaps the WWR category feeds (WJ-651); WorksLake's dedupe stores a listing once. No security change.
**PR:** see the PR that adds this file.
