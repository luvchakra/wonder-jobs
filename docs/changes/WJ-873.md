# WJ-873: Search coverage page (admin)

- **What:** Admin → Sources → **Search coverage** (`/platform/jobs-lake/search-coverage`). It shows what Jobs' sources return for each kind of work in each place.
  - **Weekly probes:** 30 kinds of work (software, nursing, teaching, insurance, banking, retail, trades, hospitality…) × 5 places (India, US, UK, UAE, Remote), searched through WorksLake's own search. Each search counts only results that really are that job: every word of the probe in the title (`isRealMatch`), so a TA Operations job doesn't count for "insurance underwriter". 10 or more is covered, 3–9 thin, fewer a gap; a failed search shows as "Didn't run", never as a gap.
  - **The page:** a matrix (gaps first), where the real matches came from by source, which sources couldn't be asked (Needs setup / Unavailable / Timed out), and **People's searches that found least**: candidates' own searches of the last 7, 14 or 30 days, by their words only, with the average their own matching judged relevant.
  - **Runs on GitHub, never on the site:** `.github/workflows/search-coverage.yml` runs Mondays 03:53 IST, or by Run workflow, via `apps/web/scripts/search-coverage.mjs`, with the same three secrets as the gateway collection. It stops starting probes after 40 minutes and saves part-way, so a cut-short run still shows what it measured.
- **Why:** Owner (2026-11-26): "how do i ensure job search can serve all kind of users of this app" → "yes build the coverage page". The next source to add is chosen from evidence, not guessed.
- **Notes:**
  - Probe runs are recorded as trigger `coverage`. They count in Source insights like a refresh, and never in "People's searches".
  - The report lives under the platform tenant (`wj.coverage`). Neither it nor the view holds anything about a person: the runs log carries no tenant, and real searches show only their words.
  - Read-only: nothing here changes a source.
