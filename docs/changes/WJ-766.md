# WJ-766 · Billing (shared) · DONE

**What:** Admin → Billing → Payments drops characters nobody sees from a pasted Razorpay Key ID or secret before checking them. These are zero-width, non-breaking and byte-order marks, and line breaks: anything that isn't a letter, a digit or `_`.
- The secret field shows how many characters it holds; Razorpay's secrets have 24.

**Why:**
- Owner, 2026-11-06: a pair they had just generated was refused ("i can confirm the pair is correct, i have just generated it").
- The Key ID was valid: Razorpay's public preferences endpoint answers 200 for it. Razorpay still answered 401 to the pair.
- A copy from Razorpay's dashboard on a phone can carry invisible characters, which `trim` keeps, and which change the secret Razorpay receives.

**Notes:**
- Razorpay keys contain only letters, digits and `_`, so nothing real is removed.
- Test: `server/billing/payments.test.ts`.
- If the pair is still refused after this, the error now names the half Razorpay refused (WJ-765).
