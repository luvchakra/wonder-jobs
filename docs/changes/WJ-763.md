# WJ-763 · Platform (shared) · DONE

**What:** Organisations' logos are ready by the time their cards ask, without the search waiting.
- **Pre-warm:** after a search's answer is sent (Next's `after`), the server warms the logos of up to 8 of its organisations the company directory doesn't have yet.
  - An organisation known only by name is found once by name (Wikidata, WJ-762) and kept under its domain.
  - An organisation recorded with a domain but no logo gets the image the source sent, if any, else its site's icon.
  - Nothing is fetched for a company that already has its logo.
- **The logo a source sends:**
  - Listings carry it as a new optional field: `companyLogo` on a posting, `employer.logoUrl` on an opportunity.
  - It's a hint: https only, never shown directly, stored once for the organisation's domain, and served like every other logo (`/api/company-logo`, CDN-cached).
  - Module sessions map their sources' fields to it (JSearch's `employer_logo`, an event organiser's image, …).
**Why:** Owner, 2026-11-06: "how to get the logo on the fly without compromising on performance".
**Notes:**
- The search response time is unchanged: warming runs after the answer.
- A source's image URL is fetched only on a public https host (`checkDestination`), with no redirects, and kept only if it is a real bitmap image (SVG refused, as before).
- Outside a request (tests, scripts) nothing is warmed.
