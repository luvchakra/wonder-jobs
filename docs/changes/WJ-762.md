# WJ-762 · Platform (shared) · DONE

**What:** Logos show for organisers and sellers that only a name identifies, and for every module's listings that do have a domain.
- **By name:** when a card asks for a logo by name (`/api/company-logo?n=`) and the company directory doesn't know the name, the server looks it up once on Wikidata. A match counts only when its label is exactly the name, it isn't a person, and it states an official website (P856) that can be an organisation's own. The company is then kept under that domain (one row, shared with every module). Its logo comes from its own site, else its Wikidata logo, and the CDN serves it from then on. A name that matches nothing isn't looked up again for a day.
- **Every module:** every module's search results now record their organisations' reported domains in the one company directory. Before, only Jobs did. Listings still stay in each module's own dataset.
**Why:** Owner, 2026-11-06: Events showed "P" instead of PayPal's logo. Root cause: Devpost names the organiser ("PayPal") without its website, and the directory only knew companies that came with a domain, from Jobs' listings only.
**Notes:** No change to search speed: the lookup happens only when a card asks for a logo (lazy, then CDN-cached for a week), never during a search. The only outside calls are to wikidata.org and the official site Wikidata states; a name sent with a domain the directory refuses still fetches nothing (test kept). No other security change.
