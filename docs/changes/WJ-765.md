# WJ-765 · Billing (shared) · DONE

**What:** Admin → Billing → Payments says why Razorpay refused a key pair, and test keys can be saved anyway.
- **Why it was refused:**
  - Before, a refusal only said "Razorpay refused this Key ID and secret".
  - Now Razorpay is also asked about the Key ID alone (its public checkout preferences, no secret needed). The message then says which half is wrong: an unknown Key ID, or a secret that isn't this key's. A secret is shown only once, so the fix for the second is to regenerate the key.
- **Show:** the Key secret field has a Show button, to check what was pasted.
- **Save test keys without checking:** offered after a refusal, for `rzp_test_…` keys only.
  - The page then shows the keys as refused, and payments stay off until Razorpay accepts them.
  - Live keys must always pass the check.

**Why:** Owner, 2026-11-06, with a screenshot of the refusal: "check why this failed. allow to save test key as well for testing purpose".

**What we found:**
- The Key ID entered, `rzp_test_TwlZPwmXuqwcSt`, is a real key: Razorpay's preferences endpoint answers 200 for it.
- Razorpay answered 401 "Authentication failed" to the pair, so the secret entered isn't that key's secret.

**Notes:**
- Saving unchecked is recorded in Billing → History (`checked: false`).
- Tests: `server/billing/payments.test.ts`.
