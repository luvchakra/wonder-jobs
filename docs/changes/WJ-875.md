# WJ-875: One posting from two gateway boards is listed once

- **What:** WorksLake's canonicalisation never merged two records of the same source, on the rule that a source lists a posting once. The WorksLake Data Gateway is one source with many boards behind it, so the same posting collected from two boards stayed as two listings. A source can now be marked `aggregates` (the gateway sources are). Two of its records merge when they share an apply URL, or the same description in the same place. They never merge on title, employer and place alone, which two requisitions also share. Every other source behaves as before.
- **Why:** Owner (2026-11-28): the same "Principal Technical Account Manager" job at Ping Identity appeared twice, both "via WorksLakeDG".
- **Notes:**
  - Production data couldn't be read from this session, so the two records weren't inspected. The cause is from the code: `groupObservations` refused any same-source merge.
  - Jobs' own guard (WJ-893) still lists identical cards once; this fixes it at the source, for every module that reads the gateway.
  - Tests: one posting held twice merges; two requisitions with different descriptions stay apart; a single-origin source is unchanged.
