# WJ-767 · Billing (shared) · DONE

**What:** Razorpay Standard Checkout with orders. Plans are paid a month at a time when the Razorpay account has no Subscriptions product. The admin key check no longer refuses good keys.
- **Why keys were refused:**
  - With the owner's test keys, Razorpay answers 200 for Payments and Orders, but 401 "Unauthorized" for Plans and Subscriptions. The account doesn't have Razorpay's Subscriptions product.
  - The admin's key check used Plans, so it called good keys refused.
  - It now uses Payments, which every account has. The page shows whether Subscriptions is on.
- **Paying, month by month:** used when the plan has no Razorpay plan, which is always the case without Subscriptions.
  - **Create the order:** "Upgrade to Pro" creates a Razorpay order on the server (`/api/billing/checkout`). The amount is the plan's own price on Prices, never the browser's.
  - **Pay:** Razorpay's checkout window opens with that order (`order_id`).
  - **Verify:** `/api/billing/confirm` checks the signature, HMAC-SHA256(`order_id|payment_id`, Key secret). It then reads the order from Razorpay and unlocks the plan only when Razorpay says it is paid in full.
  - **The month:** it runs from now, or from the end of the current paid month when paying again for the same plan. The card shows "Paid until …" and "Pay for another month". Nothing renews or charges by itself, and there is nothing to cancel.
- **Webhook:** `order.paid` is read too; tick it in Razorpay's webhook. Whichever arrives first, the confirmation or the webhook, the payment is recorded once (ledger id `order:<id>:paid`).
- **Daily reconciliation:** settles a paid order nobody confirmed, and closes one left unpaid for a week.
- **Prices:** without Subscriptions, Change price creates no Razorpay plan; a paid month charges the plan's price. With Subscriptions on, everything works as before (plans that renew by themselves).

**Why:** Owner, 2026-11-06: "Integrate Razorpay Standard Web Checkout … create orders … checkout button with payment modal … verify payment signature", with the test key pair. Razorpay was already integrated (subscriptions), so only the missing parts were added: no second checkout, no `.env` with keys, and no `razorpay` npm package (the REST calls already exist).

**Notes:**
- **Keys:** the owner's keys are entered on Admin → Billing → Payments (encrypted, WJ-764), not in a `.env` file or the code. The Key secret never reaches the browser.
- **Governance:** the plan changes only from Razorpay's own record of the order (or its signed webhook); the browser's word is never the status.
- A paid month carries `cancelAtPeriodEnd`, so it never blocks account erasure.
- **Tests:** `server/billing/payments.test.ts` and `admin.test.ts`.
- **On the owner:**
  1. Paste the keys on Payments.
  2. Add the webhook with `order.paid`.
  3. For automatic renewals, ask Razorpay to turn on Subscriptions.
