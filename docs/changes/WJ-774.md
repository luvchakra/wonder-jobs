# WJ-774 · Platform (shared) · DONE

**What:** The platform's own settings moved from the deployment's environment variables to Admin → Keys, which now has sections.
- **Email:** SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, CONTACT_FROM_EMAIL, CONTACT_NOTIFY_EMAILS, with **Send a test email** (to the admin who presses it).
- **WonderWorks AI:** WONDERJOBS_AI_KEY, WONDERJOBS_AI_PROVIDER, WONDERJOBS_AI_MODEL.
- **Push notifications:** VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY, VAPID_SUBJECT, with **Generate a key pair** when none is set.
- **Collection runner:** GITHUB_DISPATCH_TOKEN (Import now starts the GitHub collection).
- **Sources:** the existing source keys.
- Every setting the deployment still sets has **Copy from the deployment**, so its Vercel variable can then be deleted. Non-secret settings (host, port, addresses, provider, model, public key) are shown in full; secrets only masked.

**Why:** Owner, 2026-11-06: "make all the changes you suggested regarding the environment variables", after "bring them in admin portal … then decommission vercel environment variables as much as possible".

**Notes:**
- **How it reads:** one store, the existing encrypted credential store (`platformKeys.ts`, AES-256-GCM, masked on read, read at most once a minute). `withPlatformKeys()` / `platformEnv()` give the environment as the app should see it: a deployment variable that is set and non-empty wins, else the admin's value. The mailer, the platform AI, push, the import route's dispatch, hiring's team address and Sources → Import's mailbox check read through it.
- **The GitHub collection runner** reads the same store, so its mail secrets are dropped from the workflow; it needs only Supabase, the encryption key and the gateway tokens.
- **Not moved, by design:** the Supabase URL and keys, `SECRET_ENCRYPTION_KEY` (the store's own key), `JOBSLAKE_ADMIN_EMAILS` (who may open the admin must not be editable from inside it), `CRON_SECRET` (its callers hold it), and `NEXT_PUBLIC_SITE_URL` (build-time).
- **Audit:** key changes by name only; "platform_email.tested" and "platform_key.generated" with their outcome. No value is ever logged or returned.
- **Tests:** `platformKeys.test.ts` (settings view, plain vs masked, copy from the deployment); the Keys test rule now covers source keys only; mocks updated for `loadPlatformAI`; the push test's mock is hoisted.
- **Not yet seen on screen** (the site is paused): the Keys page sections were type-checked and linted, not viewed.
- **On the owner:** after the new deployment is up, press Copy from the deployment on each Email, AI and Push setting (or type them in), press Send a test email, then delete those variables in Vercel.
