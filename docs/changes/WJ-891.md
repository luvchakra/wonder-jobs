# WJ-891 · Jobs · DONE

**What:** A role with its own résumé file now takes its skills from that file, plus any skills added to the role by hand. Skills copied from My profile when the role was made no longer apply. The role's form shows the file's skills with the note "from <file>, plus any you add". The same skills feed what's built for the role's jobs: the résumé, cover letters and answers.

**Why:** Owner, 2026-11-27: "Use the file's skills". The answer to WJ-890's caveat: a role made with Add a role is prefilled with My profile's skills, and those were overriding the file's, so Kunal's IAM could reach Deepak's résumé.

**Notes:**
- `domain/career/roleFile.ts::fileRoleSkills` decides which skills count.
  - A role's own skill counts as hand-added only if My profile doesn't have it. Copied skills are therefore recognised without any stored flag.
  - Existing roles need no migration: their copied skills simply stop applying. The next save of the role's form drops them from what's stored.
  - A hand-added skill wins over the file's same skill (its level).
- What the form stores for a file role is only what was added or changed by hand. The file's own skills always come from the file, so a replaced file brings its new skills.
- Limits:
  - A skill added by hand that My profile also has counts as copied.
  - Removing one of the file's skills in the form doesn't stick, because it comes back from the file.
  - Role searches' scoring still uses the role's stored skills (scoring doesn't read files).
- Tests in `roleFile.test.ts`:
  - Reinsurance with Deepak's file shows only the file's skills, never Kunal's IAM;
  - skills added by hand are kept and win;
  - a role without a file is unchanged.
- Checked at 390px:
  - a new role shows My profile's copied skills;
  - choosing Deepak's résumé shows only "Treaty reinsurance, Claims", with the note naming the file;
  - a skill added by hand is kept;
  - no sideways scroll.
- No automation, AI or external-action change.
