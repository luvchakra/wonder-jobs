# WJ-811: WonderWorks Network — profiles, connections, and the Network tab

- **What:**
  - **Network tab:** a fifth tab in the middle of every module's bar (Find · Saved · Network · Pipeline · You), the same page in every module (`/app/network`). The bottom bar is restyled: a line on top of the current tab and the brand colour, no pill.
  - **Network profile** (opt-in, `/app/network/profile`): built from the Career Profile. The member chooses who can find them, who sees each part (Everyone / Connections / Hidden), who may ask to connect, and which statuses to show (Open to work, Hiring, Looking for a co-founder, Offering services). The full name shows to everyone by default (owner's choice).
  - **People:** search by name, skill or company, and People you may know with the real reason (mutual connections, shared skills, new on the network).
  - **Connections:** a request with an optional "how do you know them" and note; Accept or Ignore (ignoring is never revealed); Withdraw; Remove; Block and Report.
  - **A member's profile page** in a LinkedIn-like layout, with shared skills highlighted.
- **Why:** Owner request (2026-11-20): LinkedIn-style networking across the app, as the middle tab, with Co-founders' Connections kept separate.
- **Notes:**
  - Migration `0051_network.sql` adds `network_profiles`, `network_connections`, `network_messages` and `network_updates` (the last two are used by the next PR: messages, one inbox, Updates). Until it is applied, the Network tab says it is unavailable; nothing else changes.
  - **Security / governance:** a third cross-tenant read, recorded in CLAUDE.md.
    - Only a member on the network can see other members, and only as a `MemberView` filtered by each part's tier.
    - Members are addressed by a public id; account ids, email and phone never leave the server.
    - A block hides both ways and is never announced. A connection row can be changed only by its two people, with compare-and-set.
    - A request goes through `resolveCapability("network.connect")` and is audited (`CONNECTION_REQUESTED`, `CONNECTION_ACCEPTED`). `network.message` is declared for the next PR. Neither has a settings row yet; the Connect sheet shows what is sent before Send.
    - Notifications name nobody ("You have a new connection request").
  - A status turned on, or a new current role, is recorded as an update when the member keeps "Tell my connections" on; the Updates tab that shows them comes in the next PR.
  - Tests: `server/network/network.test.ts` (tiers, opt-in, find-by, requests, mutuals, block, updates), `domain/network/policy.test.ts`, `modules/nav.test.ts`; GJ-008 now expects five tabs.
